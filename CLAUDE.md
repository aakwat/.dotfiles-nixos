# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
nix flake check                                    # evaluate, no build — fastest check
nixos-rebuild build --flake ~/.dotfiles#genius     # full build, changes nothing
sudo nixos-rebuild switch --flake ~/.dotfiles#genius
nix flake update nixpkgs                           # bump a single input
nix eval ~/.dotfiles#nixosConfigurations.genius.config.<option>
```

No test suite. `nix flake check` plus `nixos-rebuild build` is the
verification loop — use them instead of `switch` when validating a change.

No install script, by design. Setup lives in README.md.

The working copy on the author's Arch machine sits at
`~/personal/.dotfiles-nixos`, but the deployed path is always `~/.dotfiles`,
which `modules/home/links.nix` resolves against.

## Architecture

One flake, one host. Three layers, each importing the next:

1. `flake.nix` — inputs (nixpkgs unstable + home-manager) and one
   `nixosConfigurations.genius`. home-manager runs as a NixOS module
   (`useGlobalPkgs`, `useUserPackages`), so `nixos-rebuild switch` applies both
   layers; there is no separate `home-manager switch`.
2. `hosts/genius/configuration.nix` — machine-specific only: bootloader,
   hostname, `resumeDevice`, `stateVersion`, and `hardware-configuration.nix`
   (generated by `nixos-generate-config`, never hand-edited). It imports
   `modules/system`.
3. `modules/system/default.nix` and `modules/home/default.nix` — plain import
   lists. **A new module file does nothing until it is added to the relevant
   `default.nix`.**

`kwat` is hardcoded in `flake.nix`, `modules/home/default.nix`,
`modules/system/users.nix` and `modules/system/desktop.nix` (greetd). A second
host or a rename means threading those through `specialArgs` — do not scatter
more literals.

### Packages live in exactly two files

`modules/system/packages.nix` (system-wide) and `modules/home/packages.nix`
(user). Do not add `environment.systemPackages` or `home.packages` to a
service module — the module system merges them silently, so a stray list is
invisible until someone greps for it.

Exception: a package that is only an implementation detail of one module
(`pkgs.tuigreet` inside the greetd command) stays inline.

### config/ and scripts/ are not Nix

`modules/home/links.nix` symlinks `config/*` into `~/.config` and `scripts/*`
into `~/.local/bin` with `mkOutOfStoreSymlink` — links point at the working
tree, not `/nix/store`. So:

- Editing a file under `config/` takes effect immediately, no rebuild. Adding
  or removing one does need a rebuild, because the link table changes.
- The repo must stay at `~/.dotfiles` or every link dangles.

`wallpapers/` is linked the same way, to `~/Pictures/Wallpapers`.

`config/mango` and `config/foot` have no Arch counterpart — they replaced the
niri and kitty configs and are maintained here only.

The rest are a *snapshot* of the author's Arch setup, not a live mirror —
changes made on the Arch machine must be copied across. That is how a waybar
module went missing once. To find drift:

```sh
for d in waybar mako tofi hypr gtk-3.0 gtk-4.0 yazi zellij nvim; do
  diff -rq ~/.dotfiles/config/$d ~/.dotfiles-arch/.config/$d >/dev/null 2>&1 || echo "DRIFT: $d"
done
```

KDL, JSONC, TOML and Lua stay in their own formats — porting them into Nix
option syntax was tried and reverted.

**A home-manager `programs.*` module that writes the same path as a symlink
collides at activation.** `programs.foot` and `programs.neovim` are therefore
not used; those packages come from `packages.nix` and their config from
`config/`. Check for this before enabling any new `programs.*` module whose
config directory exists in `config/`.

### Conventions

- `system.stateVersion` and `home.stateVersion` are frozen at install time.
  Never bump them; they are not a version to keep current.
- Verify every package name before writing it:
  `nix eval --impure --expr 'with import <nixpkgs> {}; <name>.name'`. Renames
  are common (`du-dust`→`dust`, `swww`→`awww`) and the error names the
  replacement.
- Clear deprecation warnings when `nix flake check` reports them; they become
  errors a release or two later.
- `/nix/store` is world-readable. Never inline a secret or `builtins.readFile`
  a key into a derivation — sops-nix or agenix, or nothing.
- `modules/system/security.nix` holds deliberate hardening. Two options were
  considered and rejected: strict DNSSEC (breaks captive portals) and
  `unprivileged_userns_clone=0` (breaks the Chromium sandbox and nix build
  sandboxing). Do not add them.
- `modules/home/programs/git.nix` signs commits with an SSH key. If
  `~/.ssh/coffee.pub` is missing, every commit fails.
- Keep comments short, and only where the reason is not obvious from the
  option name.
